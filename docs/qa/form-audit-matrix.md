# Form audit: role matrix

One row per write endpoint (every form the application can submit), one column per perspective. Each cell is the **best
outcome** that perspective achieved for that form. Generated by `scripts/form-audit-docs.py` from
`storage/app/form-audit/results.jsonl`; regenerate after an audit run (`FORM_AUDIT=1 php artisan test tests/Audit/FormAuditTest.php`).

| Cell | Meaning |
|---|---|
| `OK` | The form was submitted with valid input and the application accepted it. |
| `no` | Refused as designed: the role lacks the route's permission, or the caller is not signed in. |
| `pol` | Refused by a policy or record rule although the role passes the route's permission check (ownership, assignment, state, plan or product). Expected for most roles; reviewed per form in `unverified-forms.md`. |
| `422` | The form reached validation or a workflow rule that the automatic input could not satisfy. |
| `nf` / `404` | No record of the required kind existed, or the record is hidden from that role. |
| `biz` | A business-state refusal (402/409/429, e.g. subscription state). |
| `n/a` | No pending approval of that kind existed to act on. |
| `500` | A server error. See the findings. |
| (blank) | That perspective was not run for this form (for example tenant roles on platform-only forms). |

Perspectives: `guest` (not signed in), `SA` (platform super admin), `admin`, `editor`, `lead` (project lead), `viewer`, `mgr` (manager),
`hrm` (HR manager), `pay` (payroll manager), `emp` (employee), `hrx` (HR executive), `fin` (finance admin), `aud` (auditor), plus `appr`
(the user the approval workflow assigns) and `req` (the person who made the request) for approve/reject/withdraw/cancel forms.
Each tenant role was exercised as a user holding **only** that role.
